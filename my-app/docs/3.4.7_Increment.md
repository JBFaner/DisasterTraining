# 3.4.7 Increment

## Overview

An **Increment** is a concrete stepping stone toward the Product Goal. Each sprint produces a usable Increment that is additive to all prior Increments and thoroughly verified to ensure that all Increments work together.

For the Disaster Preparedness Training and Simulation System, each Increment must satisfy the Definition of Done and be demonstrable to LGU stakeholders.

## Definition of Done (Project-wide)

An Increment is considered Done when:

1. Code is implemented and peer-reviewed
2. Feature works in the staging / production-like environment
3. Role-based access is enforced where required
4. Basic automated or manual tests pass for the sprint scope
5. Documentation / backlog status is updated
6. Product Owner (or project adviser / LGU counterpart) accepts the demo

## Increment History

### Increment 1 — Authentication and User Management (Sprint 1)

**Goal:** Secure multi-portal access for admin and participants.

**Delivered:**
- Participant and admin login portals
- OTP-based admin verification
- Role-based access control (LGU Admin, Trainer, Staff, Participant, Super Admin)
- Session management and timeout
- User registration with email verification

**Value:** LGU can securely onboard users and separate admin vs participant workflows.

### Increment 2 — Training Content and Scenario Foundation (Sprint 2)

**Goal:** Publish training modules and prepare simulation content.

**Delivered:**
- Training module CRUD and lesson content management
- Scenario / AI-assisted training content support
- Audit logging for administrative actions
- Initial UI/UX design system (colors, icons, components)

**Value:** Trainers can publish preparedness modules that participants will later consume.

---

### Increment 3 — Campaign, Participants, and Attendance (Sprint 3)

**Goal:** Connect training intelligence to participant registration and attendance.

**Delivered:**
- Campaign request / Training Intelligence submission flow
- Participant registration and attendance tracking
- File storage for training assets
- User activity monitoring foundations

**Value:** Approved campaigns can open registration; LGU can track who joined training.

---

### Increment 4 — Evaluation and Scoring (Sprint 4)

**Goal:** Measure learning outcomes after modules and simulations.

**Delivered:**
- Lesson quiz evaluation hub (participant-centric views)
- Final AI scenario evaluation results
- Evaluation analytics (pass/fail, scores, review of answers)
- Printable evaluation summaries

**Value:** Admins can prove training effectiveness and identify participants ready for simulation.

---

### Increment 5 — Simulation Planning, Lifecycle, and Partner Integrations (Sprint 5)

**Goal:** Run simulation events end-to-end with external partners.

**Delivered:**
- Exercise Plan / template reuse path
- Simulation event readiness checklist and lifecycle (publish, monitor, complete)
- Campaign System outbound integration (Training Intelligence push)
- CPSQC Patrol marshal request / availability-aware assignment flow
- Certification issuance and eligibility tracking (internal)
- Hazard Assessment profile for Barangay San Agustin

**Value:** LGU can move from Approved Campaign to Exercise Plan to Publish to Monitoring with partner systems connected.

---

### Increment 6 — Ops Hardening, Role Model & Capstone UX (Sprint 6)

**Goal:** Align access control and demo artifacts with defense / LGU pilot reality.

**Delivered:**
- Refined RBAC: Admin full access; Lead Trainer = Full Operations; Assistant Trainer = personnel/roster only; Evaluator = evaluation + attendance
- Viewer removed from assignable UI
- Settings Appearance (light/dark theme)
- Event equipment request (ops-gated)
- Print helpers for operational lists
- Realistic Word supporting documents for San Agustin hazard profile (flood / multi-hazard / BDRRM note with references)

**Value:** Roles match organizational practice; hazard documents are defense-ready; operators get clearer UX.

## Current Product Increment (as of 2026-08-12)

The system currently delivers a coherent Increment covering:

| Area | Capability |
|------|------------|
| Auth & Security | OTP / centralized login, refined RBAC, audit logs, CSRF protections, HTTPS |
| Roles | Admin · Lead Trainer · Assistant Trainer · Evaluator · Staff · Participant |
| Training | Modules, lessons, quizzes, AI scenarios (Gemini), print helpers |
| Campaigns | Training Intelligence submit + Campaign Planning approve/reject |
| Simulation | Template → readiness → publish → monitoring · equipment requests |
| Patrol | CPSQC request/assign with unavailable officer filtering |
| Hazard | San Agustin profile + Word supporting documents |
| Evaluation | Lesson quizzes + final scenario scoring |
| Certification | Internal issuance / eligibility / verification |
| UX | Light/dark theme (Settings), notifications, backup tools |
| Analytics | Dashboards, evaluation stats, security/audit analytics |

This Increment is deployed on the Hostinger VPS production environment and is usable by LGU administrators and participants.
