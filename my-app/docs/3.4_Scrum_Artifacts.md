# 3.4 Scrum Artifacts

## Overview

Scrum Artifacts provide transparency and opportunities for inspection and adaptation in the development of the **Disaster Preparedness Training and Simulation System**. This chapter presents the Product Backlog, Sprint Backlog, and Increment as maintained by the development team.

## Scrum Artifacts Used

| Artifact | Purpose in This Project |
|----------|-------------------------|
| **Product Backlog** | Ordered list of all features, security controls, standards, integrations, and analytics work needed for the system |
| **Sprint Backlog** | Selected Product Backlog items plus detailed tasks for each sprint cycle |
| **Increment** | Working, usable product version produced at the end of each sprint that meets the Definition of Done |

## Product Backlog Structure

The Product Backlog is organized into the following sub-sections:

1. **3.4.1** Product Backlog (Functional User Stories)
2. **3.4.2** Product Backlog for EIS Information Security
3. **3.4.3** Product Backlog for EIS Standards (UI/UX)
4. **3.4.4** Product Backlog for EIS Integration
5. **3.4.5** Product Backlog for Analytics
   - **3.4.5.1** Application System Analytics
   - **3.4.5.2** EIS Analytics
6. **3.4.6** Sprint Backlog (User Stories)
7. **3.4.7** Increment

## Ordering and Refinement

Product Backlog items are ordered by:

1. Business value to LGU training operations
2. Regulatory / information security criticality
3. Technical dependency (foundation before advanced features)
4. Partner integration readiness (Campaign Planning, CPSQC Patrol, and related systems)

Backlog refinement is performed before each sprint planning session to clarify acceptance criteria, estimate effort, and update status (Completed / In Progress / Planned).

**Current sprint (as of 2026-08-12):** Sprint 7 — Defense documentation & remaining integrations.  
**Last completed increment:** Sprint 6 — Ops hardening, role model, theme, hazard Word docs.

## Status Legend

| Symbol | Meaning |
|--------|---------|
| Completed | Implemented, tested, and available in the deployed system |
| In Progress | Actively being developed in the current or recent sprint |
| Planned | Accepted for future sprints; not yet started |
