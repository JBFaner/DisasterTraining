3.3 Sprint Cycles

Overview

The Disaster Preparedness Training and Simulation System follows Agile Scrum methodology with structured sprint cycles to ensure iterative development and continuous improvement. Each sprint produces a usable product Increment that can be demonstrated to LGU stakeholders.

Sprint Structure

Each sprint cycle follows a standard Scrum workflow:

  1. Sprint Planning — select Product Backlog items and create the Sprint Backlog
  2. Daily Stand-ups — short coordination on progress, blockers, and next steps
  3. Development & Testing — implement stories against the Definition of Done
  4. Sprint Review — demo the Increment to stakeholders
  5. Sprint Retrospective — identify process improvements for the next sprint

Table 2: Scrum Board (Workflow Columns)

To DoIn ProgressReview / TestingDone
Backlog tasks accepted for the sprintActively coded / designedQA, peer review, staging checkMeets Definition of Done and accepted

Sprint Duration

  • Sprint Length: 2 weeks per sprint (extendable to 3 weeks for heavy integration work)
  • Sprint Planning: First day of each sprint
  • Daily Standups: Daily 15-minute meetings
  • Sprint Review: End of sprint demonstration
  • Sprint Retrospective: Post-sprint improvement session

Sprint Goals

SprintPrimary GoalFocus Areas
Sprint 1Core authentication and user managementLogin portals, OTP, RBAC, sessions
Sprint 2Training modules and scenario managementModules, lessons, scenarios, UI foundations
Sprint 3Event planning and participant registrationCampaigns, registration, attendance
Sprint 4Evaluation and scoring systemLesson quizzes, final scenario, analytics
Sprint 5Simulation lifecycle and partner integrationsExercise plans, Campaign API, CPSQC Patrol, certification foundations
Sprint 6Reporting and analyticsEngagement metrics, trends, report builder
Sprint 7Integration and API developmentSMS, SSO exploration, API docs, security reporting
Sprint 8UI/UX enhancements and optimizationAccessibility, performance, final QA

Ceremonies and Roles

RoleResponsibility
Product OwnerPrioritizes Product Backlog; accepts Increments
Scrum Master / Project LeadFacilitates ceremonies; removes blockers
Development TeamDesigns, builds, tests, and documents features
Stakeholders (LGU)Provide feedback during Sprint Reviews

Definition of Done

A task is considered Done when:

  1. Code is written and reviewed
  2. Unit / feature checks pass for the sprint scope
  3. Integration checks pass where partner APIs are involved
  4. Documentation and backlog status are updated
  5. Feature is verified on staging or production-like environment
  6. Product Owner approval is received in the Sprint Review

Product Backlog items are ordered by:

  2. Regulatory / information security criticality

INT-1: Certification Tracking System Integration

Description

Implement a comprehensive certification tracking system that integrates with the existing evaluation and attendance system to automatically track, issue, and manage participant certifications.

User Stories

As a System Administrator,

  • I want to view all issued certifications in a centralized dashboard
  • I want to track certification expiration dates
  • I want to generate certification reports
  • I want to revoke or invalidate certifications when needed

As an LGU Admin,

  • I want to see which participants are eligible for certification
  • I want to issue certificates to eligible participants
  • I want to track certification status for my organization's participants
  • I want to export certification data

As a Participant,

  • I want to view my earned certifications
  • I want to download my certificates
  • I want to verify my certification status
  • I want to see my certification history

Features/Tasks

  1. Certification Database Schema

- Create certifications table

- Link to participant_evaluations table

- Track certification metadata (issue date, expiry date, certificate number)

- Status: ✅ Completed (via is_eligible_for_certification field)

  1. Certification Eligibility Engine

- Automatically determine eligibility based on:

- Evaluation score (pass threshold)

- Attendance status (completed)

- Event completion

- Status: ✅ Completed

  1. Certificate Generation

- PDF certificate template

- Dynamic content (name, date, event, score)

- Digital signature support

- Status: 🚧 In Progress

  1. Certification Dashboard

- View all certifications

- Filter by participant, event, date range

- Search functionality

- Status: 📋 Planned

  1. Certification API Endpoints

- GET /api/certifications - List certifications

- GET /api/certifications/{id} - Get specific certification

- POST /api/certifications/verify - Verify certificate

- Status: 📋 Planned

  1. Certificate Verification System

- Public verification page

- Certificate number lookup

- QR code generation for certificates

- Status: 📋 Planned

  1. Certification Export

- CSV export

- PDF report generation

- Bulk certificate download

- Status: 📋 Planned

Technical Requirements

  • Database: Extend `participant_evaluations` table or create new `certifications` table
  • Storage: Store certificate PDFs in `storage/app/certificates/`
  • API: RESTful API for certification management
  • Security: Role-based access control for certification operations

Integration Points

3.4.7 Increment

Overview

An Increment is a concrete stepping stone toward the Product Goal. Each sprint produces a usable Increment that is additive to all prior Increments and thoroughly verified to ensure that all Increments work together.

For the Disaster Preparedness Training and Simulation System, each Increment must satisfy the Definition of Done and be demonstrable to LGU stakeholders.

Definition of Done (Project-wide)

An Increment is considered Done when:

  1. Code is implemented and peer-reviewed
  2. Feature works in the staging / production-like environment
  3. Role-based access is enforced where required
  4. Basic automated or manual tests pass for the sprint scope
  5. Documentation / backlog status is updated
  6. Product Owner (or project adviser / LGU counterpart) accepts the demo

Increment History

Increment 1 — Authentication and User Management (Sprint 1)

Goal: Secure multi-portal access for admin and participants.

Delivered:

  • Participant and admin login portals

  • Session management and timeout
  • User registration with email verification

Value: LGU can securely onboard users and separate admin vs participant workflows.
